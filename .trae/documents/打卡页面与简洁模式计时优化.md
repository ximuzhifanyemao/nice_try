# 打卡页面与简洁模式计时优化计划

## 摘要

本次优化聚焦两个用户确认的方向（"数据可靠性"优先）：

1. **打卡页面（英语长难句打卡）数据可靠性**：进入页面本地缓存秒出 + 后台刷新，翻译输入/打分结果/AI 批改结果本地持久化（切页/刷新不丢），撤销打卡加确认框防误触。
2. **简洁模式计时跨零点丢失修复（真实 bug）**：计时跨午夜后会被静默清零且时长丢失，改为自动留存为"昨日待补记录"并给出提示，在全功能「计时」页可自动恢复合并。

## 现状分析

### 打卡页面（`src/pages/EnglishCheckin.tsx`，779 行单文件）

- 挂载时 `fetchMyCheckins(user.id)` 全量拉取 `english_checkin` 表并 `setLoading`，无本地缓存；网络慢时每次进入都会白屏闪烁。
- 翻译输入（`translations`）、打分结果（`scores`）、AI 批改结果（`aiResults`）全部只存 React state，切换页面/刷新即丢失；AI 结果丢失重调会重复消耗 AI 额度。
- `handleUndo`（L345）直接调 `deleteCheckin` 撤销最近一次打卡，无确认，误触即误删云端数据。
- 已标记生词（`markedWords`）已有 localStorage 持久化，可作为同构参照。

### 简洁模式计时保存（`src/widget/CapsuleStrip.tsx` + `src/lib/timerSync.ts`）

- `CapsuleStrip` 每秒 tick 调 `loadSharedTimer()`；`loadSharedTimer`（timerSync.ts L31）检测到 `startTime` 非今天时直接 `clearAllRunning()` 并返回 `null`。
- **Bug 链路**：23:50 开始计时 → 零点后第一个 tick → `loadSharedTimer` 认为跨天 → 清空 running → UI 秒变"选择科目开始"，已学的 10 分钟无任何提示直接丢失，PENDING 里也没有备份。
- `finishSharedTimer`（L212）的正常保存链路已完善：先 `savePendingTimer` 本地备份 → 登录且当天则 `upsertLogSafely` 写云 → 成功才清备份；未登录/跨天/失败返回提示。跨零点问题只是"没人走这个链路"。
- 全功能 `StudyTimer.tsx` 挂载时 `loadRunningTimer()` 同样会丢弃跨天计时；但其挂载后的 pending 恢复 effect（L786）能把本地备份自动并入「今日累计」——留存链路已存在，只差跨天时先备份这一步。

## 变更内容

### 1. `src/lib/timerSync.ts` — 跨零点留存（核心修复）

**新增导出函数 `settleOvernightTimer()`**（读取原始 running → 判断跨天 → 留存 → 停表 → 返回信息）：

```ts
/** 幂等。读取原始共享计时，若 startTime 已是昨天（跨午夜），把已流逝时长
 *  落为昨日待补记录（date = 计时开始那天）并停表，返回 { seconds, date }；
 *  未跨天 / 无计时 / 解析失败返回 null。 */
export function settleOvernightTimer(): { seconds: number; date: string } | null {
  const raw = localStorage.getItem(TIMER_RUNNING_KEY) ?? localStorage.getItem(LEGACY_WIDGET_KEY)
  if (!raw) return null
  let parsed: Partial<SharedTimerState>
  try { parsed = JSON.parse(raw) } catch { return null }
  if (!parsed.startTime) return null
  if (new Date(parsed.startTime).toDateString() === new Date().toDateString()) return null // 未跨天
  const state: SharedTimerState = {
    subjectId: parsed.subjectId ?? null,
    activity: parsed.activity ?? '',
    startTime: parsed.startTime,
    paused: parsed.paused ?? false,
    pausedMs: parsed.pausedMs ?? 0,
    pausedAt: parsed.pausedAt ?? null,
  }
  const seconds = computeTimerElapsed(state)
  if (seconds >= 1) {
    savePendingTimer({
      subjectId: parsed.subjectId ?? '',
      activity: parsed.activity ?? '',
      seconds,
      start: timeHm(parsed.startTime),
      end: timeHm(state.paused ? (state.pausedAt ?? Date.now()) : Date.now()),
      date: dateOf(parsed.startTime), // 昨日，供跨天补交
    })
  }
  clearAllRunning() // 停表并清理 legacy key
  return { seconds, date: dateOf(parsed.startTime) }
}
```

**修改 `loadSharedTimer()` 跨天分支（L40-L44）**：丢弃前先留存，作为所有调用点的兜底（StudyTimer 挂载、其他读取方跨天时数据也不丢）：

```ts
// 跨午夜修复：若计时开始于今天之前，先留存再丢弃（避免把时长直接弄丢）
if (new Date(parsed.startTime).toDateString() !== new Date().toDateString()) {
  settleOvernightTimer()
  return null
}
```

> 注意 `settleOvernightTimer` 里复用了文件内的 `savePendingTimer` / `clearAllRunning` / `computeTimerElapsed` / `timeHm` / `dateOf`，全部已存在，无新增依赖。`loadSharedTimer` 内部已 try/catch，`settleOvernightTimer` 自身也 try/catch 保护。

### 2. `src/widget/CapsuleStrip.tsx` — 跨零点时提示用户

tick 中先调 `settleOvernightTimer()`，若留存了时长则停表并弹出一次性提示：

```ts
useEffect(() => {
  const tick = () => {
    const settled = settleOvernightTimer() // 幂等：已处理则不再触发
    const s = loadSharedTimer()
    setRunning(s)
    setElapsed(s ? computeTimerElapsed(s) : 0)
    if (settled && settled.seconds >= 1) {
      showNote(`跨零点：已留存昨日 ${formatDuration(settled.seconds)}，可在全功能「计时」页保存`)
    }
  }
  tick()
  const id = setInterval(tick, 1000)
  return () => clearInterval(id)
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [showNote])
```

- import 增加 `settleOvernightTimer`。
- 依赖从 `[]` 改为 `[showNote]`（showNote 为 useCallback 且引用稳定，不会造成 interval 频繁重建；`formatDuration` 已 import）。
- UI 表现：跨零后 running=null → 显示"选择科目开始" + note 提示留存秒数；用户后续可在全功能「计时」页看到"已恢复精简挂件未保存的计时"toast 并保存（现有逻辑，自动闭环）。

### 3. `src/pages/EnglishCheckin.tsx` — 打卡数据可靠性

**3a. 打卡状态本地缓存秒出 + 后台刷新**（参照项目已有的 `kaoyan_week_goal_cache` 模式）：

- 模块级新增 key 与 load/save：

```ts
const CHECKINS_CACHE_KEY = 'kaoyan_english_checkins_cache'
interface CheckinsCache { userId?: string; days: number[]; savedAt: string }
function loadCheckinsCache(userId: string): Set<number> | null {
  try {
    const raw = localStorage.getItem(CHECKINS_CACHE_KEY)
    if (!raw) return null
    const c = JSON.parse(raw) as CheckinsCache
    if (!Array.isArray(c.days) || c.userId !== userId) return null // 禁止串用户
    return new Set(c.days)
  } catch { return null }
}
function saveCheckinsCache(userId: string, days: number[]): void {
  try {
    localStorage.setItem(CHECKINS_CACHE_KEY, JSON.stringify({ userId, days, savedAt: new Date().toISOString() }))
  } catch { /* 忽略配额异常 */ }
}
```

- 挂载 effect（L280-L293）改为：先读缓存秒出（同时把 `selectedDay` 定位到第一个未完成天），再后台 `fetchMyCheckins` 刷新并 `saveCheckinsCache`；fetch 失败时若有缓存则静默（不覆盖），无缓存才 `setError`：
  - 新增 `const [dataReady, setDataReady] = useState(false)` 或复用 `loading`：缓存命中时直接 `setLoading(false)` 秒渲染，后台刷新仅是静默更新。
  - `handleCheckIn` / `handleUndo` 成功后同步更新缓存（`saveCheckinsCache(user.id, Array.from(set))`）。

**3b. 翻译 / 打分 / AI 批改结果本地持久化**：

- 模块级新增三个 key（上游为 Progress 网格不参与，仅句子键 `dayIdx-sentIdx`）：

```ts
const TRANSLATION_KEY = 'kaoyan_english_translations' // Record<"d-s", string>
const SCORE_KEY = 'kaoyan_english_scores'             // Record<"d-s", number>
const AI_RESULT_KEY = 'kaoyan_english_ai_results'     // Record<"d-s", AiCorrection>
```

- 三个 state 初始化改为读缓存：`useState<Map<string,string>>(() => loadStrMap(TRANSLATION_KEY))` 等（模块内新增 `loadStrMap` 通用解析）。
- 写入点同步落盘：
  - 翻译 textarea `onChange`（L523-L528）：`setTranslations` 后把 next Map 序列化存 TRANSLATION_KEY（同时保持现有清理 scores/aiResults 逻辑，删除对应缓存 key）。
  - `handleScore`（L368）成功后存 SCORE_KEY。
  - `handleAiCorrect`（L389）成功后存 AI_RESULT_KEY；失败时删除对应 key 的缓存（避免误导）。
  - 所有存取包 try/catch（localStorage 配额/隐私模式）。
- 数据量可控：翻译约 150 天 × 5 句 × 平均 200B ≈ 150KB 级，AI 结果仅在用户实际点击批改的句子上累积，远低于 5MB 配额。
- 复用现有 `markedWords` 的持久化习惯：采用同步写（小数据），不做 debounce，实现更简单可靠。

**3c. 撤销打卡加确认框**：

- `handleUndo`（L345）开头加 `if (!window.confirm(\`确定撤销 Day ${lastDoneDay} 的打卡？\`)) return`，与 `handleDeleteSubject` 等的既有 confirm 风格一致。

## 假设与决策

- **不做**补打卡（保持顺序打卡产品行为）、连续天数展示、打卡动效——不在本次范围。
- 打卡缓存带 `userId` 校验，避免多账号切换串数据（不给缓存加过期时间，后台总是刷新保证新鲜度；这是"秒出 + 后台修正"模式）。
- 翻译/AI 结果缓存不因打卡完成而清理（可作复习材料，配额可控）；无需清理策略，配额异常时静默忽略并继续原有功能。
- 跨零点留存复用现有 PENDING 机制（`kaoyan_pending_timer`），恢复/去重逻辑全部走 StudyTimer 已有 effect（L786-L831），**不新增恢复代码**；`settleOvernightTimer` 无 user 依赖，保存与恢复天然解耦。
- `loadSharedTimer` 的兜底留存保证全功能页跨天也不丢数据；CapsuleStrip 的调用仅用于产生用户可见提示。

## 验证步骤

1. **打卡缓存**：`npm run dev` → 登录 → 进入打卡页：首进正常 fetch；再进（或断网重进）应秒出进度条与已打卡数，随后后台静默刷新。
2. **翻译/AI 持久化**：输入一段翻译并打分 → 刷新页面 → 翻译文本与分数仍在；点一次 AI 批改成功 → 刷新 → 结果仍在；错误批改后对应句子的过期结果被清除。
3. **撤销确认**：未登录时不可见；登录后可打卡 → 点撤销 → 出现确认框，取消不删、确认删除。
4. **跨零点修复**：`npm run tauri dev`（或 Web 端 widget 页面）→ 手动把 localStorage `kaoyan_timer_running.startTime` 改为昨日 23:50 的时间戳、`subjectId` 设为已有科目 → 重启/等下一次 tick → 计时应停表，胶囊条出现"跨零点：已留存昨日 …"提示 → 打开全功能「计时」页 → 应看到"已恢复精简挂件未保存的计时"toast，时长并入今日累计 → 保存到昨日记录成功。
5. **回归**：零点后未开始计时（无 running）时进入，不应出现任何提示或残留 pending；正常当日开始/暂停/结束计时功能不受影响。
