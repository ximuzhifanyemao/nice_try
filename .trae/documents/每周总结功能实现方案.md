# 每周总结功能实现方案

## Context(背景)

用户需要一个「每周总结」功能:
1. **本周 vs 上周学习情况对比** —— 学习总时长、打卡天数、日均时长、各科目时长变化、周目标完成度;
2. **反思笔记** —— 用户每周写一篇「哪块做得不够好」的文字,每周一篇,可切换周次回看历史。

现状:数据已完备 —— `LogsContext` 全局加载全部学习日志,`lib/summary.ts` 有 `getWeekRange/filterLogsByRange/computeSummary`,`lib/commitments.ts` 有周承诺查询 `fetchCommitments`。缺的是「每周对比计算」「反思笔记存储」和「页面展示」。

产品决策(已按推荐默认):入口为独立页面 `/weekly-summary` + 统计页顶部入口卡片 + 桌面侧边栏导航项;底部导航不加(已 7 个 tab 太挤);英语打卡不做(控制范围)。

---

## 一、数据库:追加 `weekly_reflections` 表

在 `supabase-schema.sql` 末尾追加「二十、每周总结反思表」,严格仿照「十九、待办清单」的幂等范式:

```sql
CREATE TABLE IF NOT EXISTS public.weekly_reflections (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  week_start DATE NOT NULL,          -- 周起点(周一),与 getWeekStartStr 口径一致
  content TEXT NOT NULL DEFAULT '',
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_weekly_reflections_user_week
  ON public.weekly_reflections (user_id, week_start);
CREATE INDEX IF NOT EXISTS idx_weekly_reflections_user
  ON public.weekly_reflections (user_id, week_start DESC);

ALTER TABLE public.weekly_reflections ENABLE ROW LEVEL SECURITY;

-- SELECT / INSERT / UPDATE / DELETE 四策略,均为 auth.uid() = user_id
DROP POLICY IF EXISTS "Users can read own weekly reflections" ON public.weekly_reflections;
CREATE POLICY "Users can read own weekly reflections" ON public.weekly_reflections
  FOR SELECT USING (auth.uid() = user_id);
-- ……(INSERT/UPDATE/DELETE 同款,照 todos 表抄)

GRANT SELECT, INSERT, UPDATE, DELETE ON public.weekly_reflections TO authenticated;
```

前端经 Supabase SQL Editor 手动执行(用户无本地 CLI 部署偏好)。

## 二、数据层:新建 `src/lib/weeklyReflections.ts`

### 反思读写
- `fetchReflection(userId, weekStart): Promise<WeeklyReflection | null>` —— `.maybeSingle()`
- `upsertReflection(userId, weekStart, content)` —— `.upsert({...}, { onConflict: 'user_id,week_start' }).select().single()`,写入 `updated_at`
- `fetchReflectionWeekStarts(userId): Promise<string[]>` —— 供历史周次下拉

### 周对比计算(复用现有工具)
- `computeWeekStat(logs, weekStart)`:过滤 `weekStart..weekEnd && !deleted_at` → `computeSummary()` → 返回 `totalHours / checkedDays / avgDaily(totalHours/7) / subjectHours(Record<subjectId, hours>)`
- `computeWeeklyComparison(logs, currentWeekStart)`:上周起点 = `addDays(currentWeekStart, -7)`;diff = 本周 − 上周;科目级 `SubjectDiff[]`(thisWeekHours / lastWeekHours / diff / improved),按本周时长降序,`getSubjectById(id)?.name ?? '已删除科目'`

口径对齐:`deleted_at` 过滤参照 `WeeklyReport.tsx:45`;日均 = 总时长/7 同 WeeklyReport;打卡天数沿用 `computeSummary.checkedDays`。

## 三、页面:新建 `src/pages/WeeklySummary.tsx`

容器 / loading / error / 空态沿用 `src/pages/Summary.tsx` 范式,宽度用 `useWideLayout()`。

### 状态与数据流
- `weekStart` 初始 `getWeekStartStr()`(本周);上一周/下一周箭头用 `addDays(±7)`;下一周禁用条件 `addDays(weekStart,7) > getWeekStartStr()`(不可到未来)
- `useEffect([user, weekStart])`:切周 → 拉该周反思、重置 draft/editing
- `useEffect([user], 一次)`:拉全量 `fetchCommitments`(按 `week_start` 匹配当前周) + `fetchReflectionWeekStarts`(下拉)
- `comparison = useMemo(() => computeWeeklyComparison(logs, weekStart), [logs, weekStart])`

### 渲染结构(自上而下)
1. 标题「每周总结」
2. 周次切换栏:← 周区间 → + 「已写反思」历史下拉
3. 本周 vs 上周核心对比卡(渐变卡片 `from-indigo-600 to-violet-600`,仿 WeeklyReport):总时长 / 打卡天数 / 日均,每格带 `vs 上周` 与 ↑↓ 增减(正绿负红)
4. 科目对比卡(白卡):每行 = 科目 chip + 本周 h + ↑/↓ diff h(改进绿、下降红)
5. 周目标卡:`commit.status === 'active'` → 进行中 + 进度条(仿 WeeklyReport 127-134);`won` → 达标绿;`lost` → 未达标红;无承诺 → 空态提示
6. 反思笔记卡:仿 `LogCard.tsx` textarea 编辑范式 —— 未编辑态显示内容 + 「写反思/编辑反思」;编辑态 = textarea(placeholder「这周哪些地方做得不够好?打算怎么改进?」)+ 取消/保存;保存成功 `toast.show('反思已保存')`

### Empty 态
- 本周无记录:核心卡区显示「本周还没有记录,从今天开始吧」+ 去打卡 `Link`(仿 WeeklyReport 168-177)
- 上周无数据:diff 全部中性色显示「上周暂无数据」,不误判为下降

## 五、边界情况
1. `deleted_at` 非空日志不计入(双保险过滤)
2. 周目标仅 `active` 显示进行中,`won/lost` 显示历史结果
3. 未打卡周 → 空态引导去打卡
4. 上周无数据 → 中性提示,不当下降
5. 桌面全功能模式 `ScaleToFit` 自动缩放,无需额外处理
6. 反思保存用 `onConflict(user_id, week_start)` 幂等 upsert
