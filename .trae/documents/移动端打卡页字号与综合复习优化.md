# 移动端打卡页字号与综合复习优化

## 摘要

本次只改英语长难句打卡页（`/english-checkin`），两项需求已与用户确认：

1. **移动端主句排版**：当前手机端精读主句最小 23px，短句/长句经常出现一行只剩 2-3 个单词。把 `<640px` 的主句字号降到 19–21px、行距从 1.78 收到 1.72，并启用 `text-wrap: pretty`，让同样宽度容纳更多单词、减少最后一行只剩两三个单词的情况；桌面端字号保持不变。
2. **复习穿插生词本**：把「待复习」从单句跳转升级为**综合复习队列**——待复习句子与生词本里的单词交替出现。句子沿用现有「显示答案 → 三档自评」流程；生词卡显示单词和它所在的原句，先回忆、点一下再看释义，然后继续下一句。复习完成后给出本轮统计（复习了多少句、穿插了多少词）。

## 现状分析

### 主句排版（`src/pages/english-checkin.css`）

- `.ec-sentence`（L375-L384）当前为 `font-size: clamp(23px, 4.2vw, 34px)`、`line-height: 1.78`。手机视口（320–460px）永远取最小值 23px，而内容区宽度只有约 294–434px，平均每行只能放 5–6 个单词；语料共 727 句、平均 21 词、最长 98 词，短句和长句都容易出现「一行只剩两三个单词」的观感。
- 移动端已有 `@media (max-width: 460px)` 样式块（L2847-L2936），但主句字号没有在该断点内调整。
- 桌面端依赖同一套 `clamp`，无需改动。

### 复习链路（`src/pages/EnglishCheckin.tsx` + `src/lib/englishReview.ts`）

- 待复习数据由 `loadReviewItems(userKey)` 从逐句自评派生（`englishReview.ts` L93-L122），只包含「1-2 处有误 / 多处不懂」的句子。
- 页面已有 `reviewItems`、`reviewGroups` 派生（L638-L651），「待复习」抽屉（L2090-L2153）按 Day 分组列出句子，底部 CTA「从第 1 句开始复习」目前只是 `openReviewItem(reviewItems[0])`，跳到第一句，没有复习会话概念。
- 生词本数据在 `src/lib/vocabulary.ts`，`loadVocabulary()` 返回 `VocabDay[]`，`VocabWord` 含 `word / sentence / day / sentIdx / wordIdx / addedAt`，天然能定位到原句和原词位置。
- 词条释义优先级可用：已点开词条 `loadOpenedTerms(userKey, day)` 里的 `meaning` → `getCachedLookup(word)` → `lookupOffline(word)`（免费离线词典），无需新增 AI 调用。
- 逐句推进入口 `handleAssess`（L673-L688）在最后一句会进入完成页；`goPrev`（L690-L695）、`pickDay`（L697-L717）、`jumpToSentence`（L719-L727）目前都只服务单篇阅读，需要在复习会话中分支。

### 2. `src/lib/englishReview.ts` — 综合复习队列生成

新增类型与纯函数（放在 `loadReviewItems` 之后）：

```ts
import type { VocabWord } from './vocabulary'

export type ReviewSessionStep =
  | { kind: 'sentence'; day: number; sentIdx: number }
  | { kind: 'word'; word: VocabWord }

/**
 * 把待复习句子与生词本单词交错成一个复习队列：
 * - 每个句子先入队，再在其后按需插入 1 个生词，形成「句子 → 生词 → 句子」的节奏；
 * - 生词优先选与待复习句同句、同天、再其余生词，最多插入 min(生词数, 句子数) 个，不重复；
 * - 生词少于句子时按均匀间隔插入，不会全部堆在开头或结尾；
 * - 没有生词时退化为纯句子队列。
 */
export function buildReviewMix(items: ReviewItem[], vocabWords: VocabWord[]): ReviewSessionStep[]
```

实现要点：

1. 句子步骤按 `items` 原顺序生成。
2. 生词去重键 `${word.toLowerCase()}|${sentence}`；按「同句 → 同天 → 其它」排序成 `prioritized`。
3. `k = Math.min(prioritized.length, items.length)`，取前 `k` 个，保证一次会话里生词不重复。
4. 第 `j` 个生词插在句子下标 `Math.min(items.length - 1, Math.floor((j + 1) * items.length / (k + 1)))` 之后；`k === items.length` 时即为逐句交替。
5. 返回队列中句子数 = `items.length`，生词数 = `k`。

#### 3.3 新增函数

```ts
function exitReview() {
  setReviewSession(null)
  setReviewResult(null)
  setReviewWordRevealed(false)
  setReviewMeaning('')
  setReviewMeaningLoading(false)
}

function goToReviewStep(step: ReviewSessionStep) {
  if (step.kind === 'sentence') {
    if (step.day === selectedDay) jumpToSentence(step.sentIdx, true)
    else {
      jumpTargetRef.current = step.sentIdx
      pickDay(step.day, false, true)
    }
    return
  }
  setShowSummary(false)
  setRevealed(false)
  setActiveChunk(null)
  setActiveSheet(null)
  setActiveTerm(null)
  setReviewWordRevealed(false)
  setReviewMeaning('')
  setReviewMeaningLoading(false)
}

function startReviewSession() {
  if (reviewMix.length === 0) return
  setActiveSheet(null)
  setActiveTerm(null)
  setShowSummary(false)
  setReviewResult(null)
  setReviewSession({ steps: reviewMix, pos: 0 })
  goToReviewStep(reviewMix[0])
  scrollToPageTop()
}

function advanceReview() {
  if (!reviewSession) return
  const next = reviewSession.pos + 1
  if (next >= reviewSession.steps.length) {
    const sentences = reviewSession.steps.filter((s) => s.kind === 'sentence').length
    setReviewResult({ sentences, words: reviewSession.steps.length - sentences })
    setReviewSession(null)
    setReviewWordRevealed(false)
    setReviewMeaning('')
    return
  }
  setReviewSession({ ...reviewSession, pos: next })
  goToReviewStep(reviewSession.steps[next])
}

function revealReviewWord() {
  if (reviewStep?.kind !== 'word') return
  setReviewWordRevealed(true)
  const w = reviewStep.word
  const key = `${w.day}|${w.sentIdx}|${w.wordIdx}|${w.word}`
  reviewWordKeyRef.current = key

  const opened = loadOpenedTerms(userKey, w.day).find(
    (t) => t.sentIdx === w.sentIdx && vocabWordIdx(t) === w.wordIdx,
  )
  const cached = getCachedLookup(w.word)
  const immediate = opened?.meaning || (cached ? cached.meanings.join('；') : '')
  if (immediate) {
    setReviewMeaning(immediate)
    setReviewMeaningLoading(false)
    return
  }

  setReviewMeaning('')
  setReviewMeaningLoading(true)
  lookupOffline(w.word)
    .then((res) => {
      if (reviewWordKeyRef.current !== key) return
      setReviewMeaning(res ? res.meanings.join('；') : '本地词库暂未收录，可到生词本用 AI 查词。')
    })
    .catch(() => {
      if (reviewWordKeyRef.current === key) setReviewMeaning('本地词库暂未收录，可到生词本用 AI 查词。')
    })
    .finally(() => {
      if (reviewWordKeyRef.current === key) setReviewMeaningLoading(false)
    })
}
```

## 假设与决策

- 移动端定义为 `<640px`（与项目 `sm` 断点一致）；桌面端主句字号不变，避免影响沉浸式阅读排版。
- 仅调主句英文尺寸，意群色块、短语 chips、参考译文不在本次范围（用户已确认）。
- 综合复习队列为**一次性会话**，不新增持久化/复习进度；退出页面或手动切天即结束，避免引入新的 SRS 状态与存储。
- 生词卡释义只走免费链路（已收词条释义 → AI 查词缓存 → 离线词典），不自动调 AI；查不到时引导用户去生词本 AI 查词。
- 生词与句子按 1:1 上限交替，生词少于句子时均匀分布；不重复同一个生词，避免一次会话里反复看同一个词。
- 云端同步、打卡逻辑、生词本页面均不改动。

5. **复习闭环**：句子自评后自动进入下一格；把句子标为「全对」后待复习数量减少；队列结束显示「复习了 N 句，穿插看了 M 个生词」，两个按钮分别回到清单/继续精读。
6. **回归**：普通逐句精读的显示答案、三档自评、最后一句完成页、打卡计划抽屉、单词抽屉、添加生词本等原有流程不受影响；无生词时复习仍能按句子顺序走完。
